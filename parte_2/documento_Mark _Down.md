1. Flujo colaborativo
Supón que quieres colaborar con el repositorio de otro desarrollador. Ordena y explica los siguientes elementos:
Push, Fork, Pull Request, Clone, Merge, Commit, Review, Branch y Modificar archivos. Agrega cualquier
operación que consideres necesaria.

Fork:Es Para crear una copia del repositorio de otro compañero dentro de tu propia cuenta de GitHub Esto te permite poder modificar a tu gusto el proyecto sin afectar al otro hasta que sea aceptado

Clone:Descargas una versión o copia desde GitHub hacia la computadora local para poder trabajar en ella en el visual Code.

Branch:Creas una rama secundaria en el entorno local para desarrollar la nueva función sin alterar la rama principal

Modificar archivos:Realizamos los cambios, correcciones o agregamos el código necesario en el proyecto local.

Commit:Guardas un historial local de los cambios realizados mediante una confirmación con un mensaje dependiendo de lo que quieras decir.

Push:Envías los commits y una nueva rama desde el equipo local hacia tu repositorio en GitHub

Pull Request:Abres una petición formal desde el repositorio en GitHub hacia el repositorio del dueño principal para que te acepte tus cambios.

Review:El dueño o el equipo del proyecto original examina tu código, hace pruebas, deja comentarios o solicita ajustes si es necesario.

Merge:Una vez aceptados los cambios, el dueño de el proyecto integra la rama dentro de el repositorio original.

Diferencia entre Fork y Clone

Fork: 
Qué hace: Duplica el repositorio de otro usuario directamente en "tu propia cuenta de GitHub"
Ubicación:Todo ocurre dentro de la plataforma de GitHub.
Uso:Te permite tener tu propia versión remota de un proyecto ajeno para hacer cambios sin afectar el original ni necesitar permisos especiales de edición.

Clone:
Qué hace:Descarga una copia completa de un repositorio a tu equipo local
Ubicación:Transfiere los datos desde GitHub hacia tu computadora.
Uso:Te permite abrir el código en tu editor, modificar archivos y ejecutar el proyecto localmente.
